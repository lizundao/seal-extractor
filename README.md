# 印章提取（seal-extractor）

离线桌面工具：上传合同图片或 PDF，自动找出所有**红色印章**，逐枚预览、批量导出独立 PNG。

所有处理都在本机内存完成，不上传任何文件，无网络请求、无广告、无数据收集。MIT 开源许可，离线运行，数据留在本地。

## 功能

- 导入：拖拽 / 多选，支持 `PNG / JPG / WEBP / BMP / GIF / TIFF` 图片与**多页 PDF**
- PDF：内置 pdf.js 逐页渲染（清晰度 1.5× ~ 3× 可选），每页单独列出、单独统计
- 识别：OpenCV.js（WASM 已内嵌在 `public/opencv.js`，无需联网）
- 输出模式：**透明底红章** / 白底红章 / 原图裁切 / **去黑字裁切**
- **周边补色修复**：黑色签字、印刷字压在红章上时，用周围红色像素把被盖住的笔画补回，并清掉章内黑杂点；补色半径可调（关闭开关即输出原始效果）
- 导出：单张 PNG、所选印章打包 ZIP（附 `印章清单.csv`）、桌面版可直接导出到文件夹
- 可调参数：饱和度下限、最小边长、形状比、红色密度、笔画连接强度、重叠框合并、去噪
- 结果带编号框、置信度、尺寸与红像素占比，点击卡片可在原图上定位

## 运行

```bash
npm install

# 浏览器预览（开发模式）
npm run dev            # http://127.0.0.1:5188

# 桌面窗口（开发模式）
npm run dev:tauri

# 算法回归测试（Node 里直接跑 OpenCV，无需浏览器）
npm test              # 检测算法 + 补色修复 + 保存链路三组
npm run test:repair   # 只跑补色修复
npm run test:save     # 只跑桌面保存链路

# 构建前端
npm run build

# 编译便携 exe（不生成安装包）
npx tauri build --no-bundle
# 产物：src-tauri/target/release/seal-extractor.exe

# 生成 NSIS 安装包
npm run release
```

双击 `start-dev.bat` 可在浏览器中打开开发版；编译完成后双击 `start-app.bat` 直接运行桌面版。

## 识别原理

1. `RGBA → RGB → HSV`，取两段红色区间（`H 0~12` 与 `H 165~179`）并集，得到红色掩膜；
2. 用较大的椭圆核做**形态学闭运算**，把印章内部断裂的笔画连成整块；红色横线、红色小字只会形成细长条；
3. `findContours` 取外接矩形，按最小边长、形状比、轮廓实心度、**框内原始红色像素密度**、页面占比过滤；
4. 合并同一枚印章被拆散的重叠框，按位置编号并计算置信度；
5. 导出时用原掩膜做透明通道（3×3 软化边缘），可得到只剩红色笔画的印章图；
   边缘抗锯齿改用邻近红色而非原始黑色像素，避免透明底 PNG 出现黑色毛边。

### 周边补色（黑色压字修复）

扫描件里黑色签字 / 印刷字常被扫成**深褐红**（如 `(118,70,79)`），饱和度和色相都落在红区，会被 HSV 掩膜当成红笔画收进来——这正是"黑字去不掉"的主因。补色逻辑在 `src/repair.js`：

1. 取印章框内最亮的 25% 红色像素算出**参考红**，据此得到亮度、红度两条自适应阈值；浅红章、深红章都不会被误判；
2. 凡是明显比参考红暗、且红得不纯的像素（包括已经混进掩膜的深褐红签字）都算暗色杂墨，沿 8 个方向在 `补色半径` 内找**可信红色**像素；
3. 若存在**对向**红像素（或 ≥3 个方向有红），判定为「被盖住的红笔画」，用这些红色像素按 `1/距离` 加权均值补色，透明度置 255；
4. 其余暗色杂墨按输出模式清除：透明底→透明、白底/去黑字裁切→白色、原图裁切→只清掩膜内与紧贴红笔画的部分；
5. 白色留白不会被误填，不会把空心章糊成实心块；远离红笔画的正文黑字也不受影响；
6. 非「原图裁切」模式下，所有保留的笔画统一输出为参考红，暗红/褐色噪点不再混在章面上；关掉「补色修复黑色压字」即可恢复原始像素与原始章色。

黑色笔画很粗时调大「补色半径」；若发现相邻笔画被连在一起，则调小。

调参建议：

| 现象 | 调整 |
| --- | --- |
| 印章颜色浅、褪色 | 调低「红色饱和度下限」（如 40） |
| 小章漏检 | 调小「最小印章边长」 |
| 章被拆成好几块 | 调大「笔画连接强度」，或调大「重叠框合并」 |
| 红色横线 / 手写红字被当成章 | 调高「红色密度下限」、调小「形状比上限」 |
| 相邻两枚章被合并 | 调小「重叠框合并」 |

## 测试

`npm test` 包含两组：

- `tests/detector.test.mjs`：生成 1000×1400 的合成合同图（圆章、椭圆章、矩形章、褪色浅红章，外加红色横线、红字块、红色竖线等干扰），在 Node 中直接加载同一份 OpenCV.js 验证：4 枚章应全部命中，红色干扰不产生误报。结果图在 `tests/out/detected.png`。
- `tests/repair.test.mjs`：合成一枚红圆章，用深褐红签字（会被 HSV 当成红色掩膜）+ 纯黑签字压住，验证补色后透明底红色笔画增加、混进掩膜的暗色杂墨归零、去黑字裁切模式黑像素归零、远离红笔画的正文黑字保持不变。对比图在 `tests/out/repair-*.png`。真实扫描章的验证对比见 `tests/out/real-compare.png`（黑像素 R<150 从 821 降到 8）。
- `tests/save.test.mjs`：模拟 Tauri 运行时，验证写入命令使用 `dataB64`、字节数校验、扩展名自动补齐、写入失败明确抛错、取消时不写文件。

`node tests/make-pdf.mjs` 会基于该图生成两页 `tests/fixtures/contract.pdf`，可用来验证多页 PDF 的渲染与识别（实测 2 页共识别 8 枚印章）。

## 说明

- 首次打开需加载约 13 MB 的引擎，通常 1~3 秒；之后全部离线运行。
- 浏览器版导出走系统下载；桌面版会弹出保存对话框，还可以「导出到文件夹」把每枚印章直接写成独立 PNG。桌面写入由 Rust 的 `save_bytes` 命令完成，返回写入字节数供前端校验；若目标目录不可写会明确报错，不会静默失败。
- 桌面端调用 Tauri 命令时，Rust 的 `data_b64` 在 JS 里必须写成 `dataB64`（Tauri 2 默认按 camelCase 映射参数），否则保存对话框选完文件却不会落盘。
- 透明底模式只保留红色笔画，若合同本身有红色文字/表格线，可能一起保留，建议用白底或原图裁切模式核对。
- 章上有黑色签字/印刷字时保持「补色修复黑色压字」开启；若想看完全未处理的原始像素，关掉该开关并选「原图裁切」。
- 扫描件建议 200 DPI 以上；过低分辨率下细笔画印章可能漏检。

## 资源与安全边界

为避免恶意或异常文件把应用拖崩、或写到不该写的位置，程序设置了以下上限与防护：

- 单次最多导入 60 个文件、累计 200 页；单个 PDF 最多 120 页、150 MB；单张图片单边不超过 12000 px、单页像素不超过 40 MP（超大页面会自动降低渲染清晰度）。
- 桌面端写入由 Rust 命令完成并独立校验路径：仅允许写 PNG / ZIP，拒绝路径穿越、隐藏文件、Windows 保留名、系统目录与程序自身目录，单文件上限 200 MB。Tauri 的 fs scope 不约束 Rust 侧的文件操作，因此这层校验是必要的安全边界。
- 「导出到文件夹」逐枚写出，个别失败会明确列出失败项，已写出的文件不回退。
